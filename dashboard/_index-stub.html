How it works

A guardrail, not a cage.

  1. 01

    Detect before send

    The extension scans what's typed or uploaded the moment Enter is pressed — text, PDF, Word, CSV, JSON, logs and more.

  2. 02

    The employee decides

    A plain-English warning shows what was found and a redacted version. Low risk: Send redacted or Send anyway. High risk: redaction is mandatory.

    IT sees metadata only

    The dashboard gets a category, a tool, a department and an anonymous ID. Never the message, never the file.

Privacy by construction

Privacy is a database constraint, not a promise.

Most tools ask you to trust that they don't look. Shadow AI Guard makes looking impossible — and you can verify it.

Nothing to store it in

The event table has no column that can hold a message. Every text field is length-capped or limited to a fixed list.

No way to un-anonymise

FAQ

Questions security teams ask.

Can you see what my employees type?

No. Detection happens in the browser and only metadata is sent: a category, a hostname, a department, an action and an anonymous ID. The database has no column that could hold a message.

What stops someone just disabling the extension?

It's a guardrail against accidental paste-and-send, which is most real incidents. In production it's deployed through enterprise browser policy, which prevents removal. Honeytokens are the backstop: if content leaves by any route, a match proves it.

What about paraphrasing instead of pasting?

Out of scope for pattern matching. Catching meaning would require sending the content to a model — which would defeat the privacy design. We chose the guarantee.

Is this GDPR / HIPAA compliant?

Framework tags are a triage signal to help you prioritise, not a legal determination — we say so in the dashboard and in every email.

How are false positives handled?

Card numbers are Luhn-validated and a benign corpus must produce zero flags. Employees can mark a false positive with a reason, and the dashboard shows which rules are noisy.
